# Contributing

1. Open an issue before changing transaction or signing behavior.
2. Create a focused branch and keep commits narrowly scoped.
3. Run `pytest` and `ruff check .` before opening a pull request.
4. Add tests for authorization, transaction-cap, and network-safety changes.
5. Document user-visible behavior and attach test evidence to the pull request.

Security vulnerabilities must follow [SECURITY.md](./SECURITY.md), not the
public issue tracker.
